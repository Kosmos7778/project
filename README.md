## Процесс и подход
1. Аудит существующей документации и сбор требований у стейкхолдеров (интервью с разработчиком и DevOps-инженером).
2. Проектирование информационной архитектуры (карта разделов, глоссарий).
3. Написание в Docs-as-Code: ветка → PR → ревью (техлид + редактор) → сборка.
4. Валидация: линтеры (Vale), проверка ссылок, тестирование инструкций на чистой среде.
5. Поддержка: версионирование, release notes, changelog, метрики.

## Метрики и влияние
- Публикация релиза документации: с ~2 часов до ~10 минут («Телкор»).
- Ревью одного документа: с ~1,5 часов до ~40 минут («ИННОТЕХ»).
- Ручные корректировки документов: −30% («ИННОТЕХ», автоматизация на Python).
- Стилистические правки на ревью: −30% («Базис», Vale + сниппеты).
- Адаптация нового сотрудника: в 2 раза быстрее («Базис»).
- Время на стандартные блоки: −20–25% («Базис», 15 сниппетов VS Code).
- Демонстрация сквозного сценария сети: с ~60 до 15–20 минут («Телкор»).
